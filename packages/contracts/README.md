# packages/contracts — the single source of truth

The JSON Schemas in `schemas/`, the op registry in `ops/registry.json`, the parameter
allowlist in `ops/param_allowlist.json`, and the catalogs in `catalogs/` are the canonical
contract artifacts (PLAN.md Part D). TS (`ts/`) and Python (`python/`) types are generated
from them (pinned generators, `make codegen`); the C# records in `plugin/ChapterHub.Core`
are hand-maintained and CI-verified against the shared fixtures and the conformance
manifest in `fixtures/conformance/`.

## Field defaults (the no-defaults rule)

The schemas deliberately carry **no `default` keywords** — a document round-trips
byte-identically because parsing materializes nothing. Consumers apply these defaults in
code when a field is absent:

| field | default when absent | applied by |
|---|---|---|
| `walls[].is_exterior` / `is_load_bearing` / `is_demising` / `is_wet_wall` | `false` | layout validator, agents, sim |
| `walls[].fire_rating_hr` | `0` | MEP agent (E-4 penalty), spec compiler |
| `walls[].source` | `"generated"` | architectural agent diff (Part G), SI-8 checks |
| `walls[].curved_approximation` | `false` | review-card renderer |
| `doors[].flip_facing` | `false` | plugin/sim door placement |
| `doors[].swing` | required in `create_door` op; optional in layouts until the agent emits it | architectural agent |
| `rooms[].wet_zone` | `false` | MEP agent P-1 |
| `rooms[].adjacent_room_ids` | `[]` | layout validator |
| `furniture[].items[].fixture_units` | per `kind` from `catalogs/plumbing.json` | MEP agent P-1/P-3/P-4 |
| `furniture[].items[].hookups` | per `kind` from `catalogs/plumbing.json` | MEP agent |
| `furniture[].items[].clearance_front` | per catalog type (`new_construction_types.json` families); absent = `0` mm — the validator inflates it on ALL sides | interior agent, layout validator |
| `furniture[].items[].wall_seeking` | per catalog family `wall_seeking_default` | interior agent |
| `constraints.circulation_min` | `915` mm | layout validator, interior agent |
| `constraints.ada` | `false` | layout validator |
| `constraints.outlet_spacing` | `3660` mm | MEP agent E-1 |
| `constraints.style_tags` | `[]` | aidm-bridge |
| `brief.meta.confirmed_by_client` | `false` (layout-compiler refuses briefs not `true`) | layout-compiler |
| `brief.finish_tier` | `"standard"` | Phase 7 finish selection, spec compiler |
| `brief` per-item `hard` (adjacency) | `true` | layout-compiler |
| `*.confidence` | `1.0` (authored data); scan extractors always set it explicitly | review-card thresholding |

`meta.levels.slab_to_slab`, `meta.electrical.panel`: no default — when a Part G rule needs
one and it is absent, the rule emits REVIEW with a human-suppliable review-card field.

## Conformance manifest

`fixtures/conformance/manifest.json` (generated by `scripts/gen_conformance.py`,
deterministic, committed) pins verifier behavior across TS, Python, and C#: HMAC over the
exact UTF-8 bytes of `payload`, then parse → body schema/shape → TTL (boundary-inclusive)
→ seq monotonicity → op allowlist → per-op args — including negative vectors for tampering,
wrong key, sig spelling (uppercase / non-hex / non-ASCII), malformed payload, null/empty
`ops`, non-object args, non-RFC-3339 `issued_at`, replayed seq, unknown op, and invalid args.
